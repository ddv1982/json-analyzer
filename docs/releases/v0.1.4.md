# JSON Analyzer v0.1.4 - The Named Gate Holds

## The Quest
The signed release road opened, then stumbled on a name with a space in it. This release turns that break into a guarded path: Linux packages keep the JSON Analyzer identity inside the app, while release artifacts now travel under package-safe filenames that signing tools can handle.

## What Awoke
- Debian artifacts are renamed in CI to the canonical `json-analyzer_VERSION_ARCH.deb` shape before validation, signing, upload, and release publishing.
- The Linux bundle job now fails early if the Debian artifact disappears before filename normalization.
- The v0.1.4 release carries the same signed distribution flow as v0.1.3, with the package filename trap removed.

## Runes of Assurance
- The failing hosted CI log was traced to `dpkg-sig` opening `.../bundle/deb/JSON` after receiving `JSON Analyzer_0.1.3_amd64.deb`.
- Workflow YAML and shell syntax were checked after the filename normalization step was added.
- `git diff --check` passed before the release cut.

## Known Boundaries
- The APT repository currently publishes Linux `amd64` packages only.
- Curl jobs remain in-memory only; durable job history is still deferred.
- PDF export UI, auto-update metadata, and Windows signing remain outside this release.
